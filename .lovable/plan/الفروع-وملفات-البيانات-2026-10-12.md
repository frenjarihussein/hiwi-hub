# الفروع وملفات البيانات

## 1. الفروع
- في إعدادات الشركة (وعند إنشاء شركة جديدة): خيار "الشركة لها فروع" + شاشة لإدارة الفروع (رمز، اسم، عنوان).
- كل شيء يتبع فرعاً: الفواتير والمستندات، القيود، المستودعات، الصناديق والبنوك، الشيكات، المشاريع، الرواتب، نقطة البيع.
- في المستخدمين: تحديد الفرع لكل مستخدم (فرع 1، فرع 2...) أو "كل الفروع".
  - مدير الشركة والمحاسب العام: يرون كل الفروع.
  - محاسب الفرع: يرى ويُدخل بيانات فرعه فقط (الحماية في قاعدة البيانات وليس فقط في الواجهة).
- أعلى البرنامج: قائمة لاختيار الفرع الحالي (أو "كل الفروع" لمن يملك الصلاحية). الفاتورة الجديدة تأخذ الفرع المختار تلقائياً.
- التقارير والكشوف: فلتر الفرع (فرع محدد أو المجموع).
- البيانات القديمة تُنسب إلى "الفرع الرئيسي" تلقائياً.

## 2. ملف بيانات الشركة / السنة الجديدة
- تسمية الشركة "ملف بيانات" مع اسم وسنة مالية.
- زر "فتح ملف بيانات جديد" يسأل:
  - النوع: **سنة جديدة داخل نفس الشركة** أو **ملف/شركة منفصلة**.
  - ماذا تريد أن تنسخ (مربعات اختيار): شجرة الحسابات والربط، المواد والتصنيفات والوحدات، الزبائن والموردين، المستودعات، الفروع، العملات، مراكز الكلفة، المستخدمين والصلاحيات، الأرصدة الافتتاحية (حسابات الميزانية + كميات المخزون).
- سنة جديدة داخل نفس الشركة: تقفل السنة الحالية وتنشئ قيداً افتتاحياً، وتظهر قائمة لاختيار السنة المعروضة (السنوات القديمة للعرض).
- ملف منفصل: شركة جديدة بالبيانات المختارة، ويمكن التنقل بين الملفات من قائمة أعلى البرنامج لمن له حساب فيها.

## مراحل التنفيذ
1. الفروع: القاعدة، الصلاحيات، المستخدمين، اختيار الفرع، الفواتير والقيود.
2. الفروع في باقي الشاشات والتقارير.
3. معالج فتح ملف بيانات جديد مع خيارات النسخ.
4. التنقل بين السنوات والملفات.

## تفاصيل تقنية
- جدول `branches` + عمود `branch_id` (nullable) على الجداول التشغيلية، و`tenant_settings.has_branches`.
- `profiles.branch_id` (NULL = كل الفروع) ودالة `can_see_branch(branch_id)` تُضاف إلى سياسات RLS الحالية.
- `tenants.source_tenant_id` و`fiscal_label`؛ دالة security definer `clone_tenant(_src, _opts jsonb, _mode)` تنسخ الجداول المختارة مع إعادة ربط المعرفات.
- تطبيق التغييرات كـ SQL idempotent حسب ملاحظات المشروع.
